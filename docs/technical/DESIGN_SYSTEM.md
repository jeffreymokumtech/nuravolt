# NuraVolt design system

Single source of truth for the marketing site, demo app, and showcase. This
document is paste-able into a Claude conversation at claude.ai or
claude.com so the assistant there knows the exact palette, typography,
spacing, and primitive contracts before generating layouts.

When you want pixel data only, paste `design-tokens.json` from the repo
root. When you want the rules, paste this file.

> **Maintenance**: tokens come from `src/assets/styles/globals.scss` and
> `tailwind.config.ts`. The JSON export is generated by
> `scripts/export-design-tokens.mjs`. Update those two files only; don't
> hand-edit the JSON.

## 1. Palette (instrument-grade, warm)

The platform reads operational data, not a SaaS dashboard. The palette is
warm paper + cool ink so charts and KPI numbers stay the most chromatic
thing on the page.

### Surface

| Token        | Hex        | Use                                                                  |
| ------------ | ---------- | -------------------------------------------------------------------- |
| `paper`      | `#FBF9F5`  | primary background — every public/product page sits on this          |
| `paper-2`    | `#F1EEE8`  | section alt-fill, hover state for paper, card backplates             |
| `divider`    | `#D8DBE2`  | 1 px borders and HairlineRule                                        |
| `data-bg`    | `#0B0E18`  | the only allowed dark surface (DataPanel — embedded data blocks)     |
| `data-bg-2`  | `#141826`  | DataPanel header strip                                               |

### Text

| Token        | Hex        | Use                                                                  |
| ------------ | ---------- | -------------------------------------------------------------------- |
| `ink`        | `#11141E`  | headings, primary text                                               |
| `ink-2`      | `#444A5C`  | paragraph copy, sub-headings                                         |
| `ink-3`      | `#7C8294`  | mono eyebrows, labels, KPI under-text, tertiary metadata             |

### Signals (status / domain meaning)

| Token             | Hex        | Use                                              |
| ----------------- | ---------- | ------------------------------------------------ |
| `signal-positive` | `#2E8754`  | success, good news, "within tolerance"           |
| `signal-warning`  | `#C8932B`  | needs attention, warm warning, showcase pill     |
| `signal-critical` | `#D63A3A`  | failure, immediate action required               |

Opacity modifiers are supported (`bg-signal-positive/10`,
`border-signal-warning/30`) — `<alpha-value>` placeholder is configured.

### Asset accents (subtle identity, never chrome saturation)

| Token         | Hex        | Asset class       |
| ------------- | ---------- | ----------------- |
| `asset-solar` | `#2563eb`  | PV plants         |
| `asset-wind`  | `#0891b2`  | wind farms        |
| `asset-bess`  | `#7c3aed`  | battery storage   |

**Where they appear**: KpiCard top border (`border-t-2`), FleetCard top
border, asset chip on plant chrome, a 1.5 px dot in the chip.
**Where they don't**: body text, page backgrounds, primary CTAs (those
stay brand blue), nav active states.

### Brand blue (CTAs, links)

Tailwind `blue-50…blue-900` HSL scale wired in
`src/assets/styles/globals.scss`. Use plain `bg-blue-600` for primary
buttons via the `Button` primitive — never write the raw class on a
custom element.

## 2. Typography

| Token         | Class                                                            | Use                                                  |
| ------------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| display       | `text-display`                                                   | one per page max, hero h1                            |
| h1            | `text-h1 font-semibold`                                          | section heading                                      |
| h2            | `text-h2 font-semibold`                                          | sub-section heading                                  |
| body          | `text-body text-ink-2`                                           | paragraph copy                                       |
| meta          | `text-meta`                                                      | KPI under-text, labels                               |
| mono eyebrow  | `font-mono text-meta uppercase tracking-[0.08em] text-ink-3`     | precedes every section heading — load-bearing rhythm |

**Hero recipe** (used on landing, solutions, platform pages):

```tsx
<MarketingSection size="hero" as="div">
  <div className="font-mono text-meta uppercase tracking-[0.08em] text-ink-3 mb-3">
    Section category
  </div>
  <h1 className="text-h1 sm:text-display font-semibold text-ink mb-6">
    The headline.
  </h1>
  <p className="text-body text-ink-2 mb-8 max-w-2xl">
    Lead paragraph.
  </p>
  <Button size="lg">Primary CTA <ArrowRight className="w-4 h-4 ml-2" /></Button>
</MarketingSection>
```

## 3. Spacing rhythm

| Surface         | Vertical padding         | Inter-section gap | Notes                                       |
| --------------- | ------------------------ | ----------------- | ------------------------------------------- |
| `size="hero"`   | `py-24`                  | n/a               | one per page                                |
| `size="default"`| `py-16`                  | `HairlineRule`    | most sections                               |
| `size="compact"`| `py-10`                  | `HairlineRule`    | utility rows (resource CTAs, banners)       |

Inside a section: `space-y-6` between cards on product surfaces,
`space-y-8` for marketing surfaces with longer content blocks. Container
width is provided by `MarketingSection` (`max-w-7xl mx-auto px-4 sm:px-6 lg:px-8`).

Always put a `<HairlineRule />` between consecutive paper-coloured
`MarketingSection`s. Alternating `surface="paper-2"` provides a softer
break.

## 4. Primitives

These eight components implement the system. Building a page = composing
them. Never inline new card/pill/section logic — extend or add a primitive.

### `Button` — `src/components/ui/button.tsx`

```tsx
<Button size="lg">Primary <ArrowRight className="w-4 h-4 ml-2" /></Button>
<Button size="lg" variant="outline">Secondary</Button>
```

Sizes: `sm | default | lg`. Variants: `default | outline | ghost`. Never
build a new "I want a blue button" — use the primitive.

### `KpiCard` — `src/components/ui/KpiCard.tsx`

```tsx
<KpiCard
  title="Fleet capacity"
  value="48 MW"
  subtitle="12 plants · 10 operational"
  tone="brand"
  icon={Gauge}
/>

// Inside a plant page — let assetType colour every card:
<KpiCard title="Soiling loss" value="2 926 MWh" assetType={plant.asset_type} />
```

Props: `tone?: brand|positive|warning|critical|violet|cyan|slate`,
`variant?: plain|gradient`, `animated?: boolean`,
`assetType?: SOLAR|WIND|BESS` (overrides tone),
`icon?: LucideIcon`, `index?: number` (stagger animation).

**Rule**: `assetType` overrides `tone` — pass it once at the page level
and every KPI top border colours the plant's asset.

### `Pill` — `src/components/ui/Pill.tsx`

```tsx
<Pill tone="positive" variant="soft">Healthy</Pill>
<Pill tone={ASSET_TONE[plant.asset_type]} variant="soft">{label}</Pill>
```

Variants: `soft | outline | solid`. Size: `sm | md`. Exports
`ASSET_TONE`, `TIER_TONE`, `CAUSE_TONE`, `TICKET_STATUS_TONE` — pick the
tone from the map, never hardcode.

### `MarketingSection` — `src/components/ui/MarketingSection.tsx`

```tsx
<MarketingSection size="default" surface="paper-2">
  …
</MarketingSection>
```

Wraps every marketing-surface section. Provides the container, vertical
padding rhythm, and the paper/paper-2/data background choice.

### `DataPanel` — `src/components/ui/DataPanel.tsx`

```tsx
<DataPanel headerLeft="HELIOS · 30MW · SPAIN" headerRight="nuravolt.com/plant/helios" live>
  <div className="relative aspect-[16/11]">
    <Image src="…" alt="…" fill className="object-cover" />
  </div>
</DataPanel>
```

The only allowed dark instrument frame on the marketing surface. Used
for product screenshots embedded inside paper sections.

### `KPIReadout` — `src/components/ui/KPIReadout.tsx`

```tsx
<KPIReadout value="2 GW" label="Operational PV & BESS data" size="lg" />
```

Use on marketing surfaces. Mono numerics, meta-cased labels. Sizes
`sm|md|lg`, tone `paper|data`, optional `signal: positive|warning|critical`.

### `SectionCard` — `src/components/ui/SectionCard.tsx`

```tsx
<SectionCard title="Cleaning schedule" description="…" actions={<Button …/>}>
  <Table …/>
</SectionCard>
```

Product-surface card with rounded-xl, divider border, p-5, optional
header slot. `flush={true}` removes padding for full-bleed tables.

### `HairlineRule` — `src/components/ui/HairlineRule.tsx`

```tsx
<HairlineRule />
<HairlineRule orientation="vertical" />
```

1 px divider in token colour. Use between marketing sections to give
rhythm.

## 5. Page recipes

### Marketing page

```
<MarketingSection size="hero">   { hero copy + CTAs }
<HairlineRule />
<MarketingSection size="default">{ explanation / pillars }
<HairlineRule />
<MarketingSection size="default" surface="paper-2">{ proof / KPIReadouts }
<HairlineRule />
<SolutionCTA … />              { calm closing CTA }
<Footer />
```

Used by `/`, `/solutions/*`, `/platform/*`, `/about`. Reference impls:
`src/components/solutions/SolutionHero.tsx`, `src/app/solutions/pv-monitoring/page.tsx`.

### Product page (demo / showcase)

```
<PlantPageChrome>                { header + sidebar + asset chip }
  <PageHeader title="…" actions={…} />
  <SectionCard>                  { content row }
    …
  </SectionCard>
  <SectionCard flush>            { full-bleed table }
    <Table />
  </SectionCard>
</PlantPageChrome>
```

KPI bands use `<KpiCard assetType={plantAssetType} />` so the top borders
reflect the plant's asset class.

## 6. Conventions — what NOT to do

- ❌ `bg-gray-*`, `bg-slate-*` — use `bg-paper` / `bg-paper-2`.
- ❌ `text-gray-*`, `text-slate-*` — use `text-ink` / `text-ink-2` / `text-ink-3`.
- ❌ `border-gray-*`, `border-slate-*` — use `border-divider`.
- ❌ Mixing raw `text-amber-700` with `bg-signal-warning/10` — pick one
  vocabulary per element.
- ❌ Restyling shadcn primitives directly — they're remapped via
  `globals.scss`.
- ❌ Animating asset accents in product chrome — accents stay calm.
- ❌ More than one `text-display` heading per page.
- ❌ A marketing section without a mono eyebrow.
- ❌ Stock-photo gradient heroes — use a `DataPanel` screenshot instead.
